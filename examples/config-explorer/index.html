One employee's I-9, end to end — computed live in this page.

1 · The release

Forms, attributes, the policy, the automation and the compliance rules that read them ship as one snapshot. That is what lets a decision made under it be reproduced later: everything it could depend on has one id. Identical subtrees are stored once, so the node count is lower than the tree size.

2 · The lifecycle

Each step submits one fact, or lets a day pass. The engine looks up which questions depended on that input — it never scans the others. Considered is what was recomputed; flipped is what actually changed. They are different numbers, and that difference is the whole point: a rule edit can invalidate a thousand decisions and change none.

    3 · The decision is a proof

    Every node's id covers its answer, the rule that produced it, a digest of everything it observed, and its children's ids. So the tree can be checked without a database, a catalog, or trusting whoever handed it over. It also holds no plaintext — the SSN it read is not in it, though anyone holding that value can prove it was the one used.

      4 · Publish a change

      Compliance wants the I-9 required of everyone, not just caregivers. The diff is computed over content ids, so it names exactly the rules that moved and says the forms did not. Impact is answered before publishing, by looking up who read those rules.
